# organize-finances 完整强制检查清单

## 🚨 所有强制检查项（共28项）

### 第1步：文件夹结构验证（3项）

- [ ] 🔴 **强制1.1**：`📊_对账报表/` 文件夹存在
- [ ] 🔴 **强制1.2**：`📁_原始发票XML/` 文件夹存在
- [ ] 🔴 **强制1.3**：`📋_说明文档/` 文件夹存在

---

### 第2步：XML文件提取（8项）

- [ ] 🔴 **强制2.1**：必须使用 `glob(..., recursive=True)` 递归搜索
- [ ] 🔴 **强制2.2**：XML文件数量 ≥ 50个
- [ ] 🔴 **强制2.3**：每个XML必须提取 `EIid`（发票唯一ID）
- [ ] 🔴 **强制2.4**：每个XML必须提取 `LabelCode`（蓝字Y/红字N）
- [ ] 🔴 **强制2.5**：每个XML必须提取 `TotalTax-includedAmount`（金额）
- [ ] 🔴 **强制2.6**：每个XML必须提取 `BuyerName`（客户名称）
- [ ] 🔴 **强制2.7**：XML解析成功率 ≥ 95%
- [ ] 🔴 **强制2.8**：所有发票ID必须唯一（无重复）

---

### 第3步：红字发票识别（6项）

- [ ] 🔴 **强制3.1**：必须统计蓝字发票数量
- [ ] 🔴 **强制3.2**：必须统计红字发票数量
- [ ] 🔴 **强制3.3**：按客户分组，分别汇总蓝字和红字金额
- [ ] 🔴 **强制3.4**：计算每个客户的净额 = 蓝字 - 红字
- [ ] 🔴 **强制3.5**：列出所有有红字发票的客户
- [ ] 🔴 **强制3.6**：如有红字，必须在报告中标注原因

---

### 第4步：完全冲红客户排除（4项）

- [ ] 🔴 **强制4.1**：找出净额 = 0 的客户
- [ ] 🔴 **强制4.2**：从对账清单中移除净额 = 0 的客户
- [ ] 🔴 **强制4.3**：生成"完全冲红客户清单"
- [ ] 🔴 **强制4.4**：在报告中明确标注"不应催款"

---

### 第5步：重复和相同金额检查（4项）

- [ ] 🔴 **强制5.1**：检查相同客户+相同金额的发票
- [ ] 🔴 **强制5.2**：对这些发票验证ID是否不同
- [ ] 🔴 **强制5.3**：ID相同→去重；ID不同→保留
- [ ] 🔴 **强制5.4**：在报告中列出所有相同金额的发票及验证结果

---

### 第6步：公司名称规范化（3项）

- [ ] 🔴 **强制6.1**：所有公司名称必须统一括号（全角→半角）
- [ ] 🔴 **强制6.2**：所有公司名称必须去除多余空格
- [ ] 🔴 **强制6.3**：规范化后的名称用于匹配，原始名称用于显示

---

### 第7步：银行流水匹配（3项）

- [ ] 🔴 **强制7.1**：银行流水中的公司名称必须规范化
- [ ] 🔴 **强制7.2**：按完整公司名分组（不要合并相似名称）
- [ ] 🔴 **强制7.3**：支持拆分支付（1张发票→多笔收款）

---

### 第8步：最终合理性验证（5项）

- [ ] 🔴 **强制8.1**：总净应收金额在 ¥50,000 - ¥10,000,000 之间

- [ ] 🔴 **强制8.3**：大额客户（>¥100,000）匹配率 = 100%
- [ ] 🔴 **强制8.4**：生成"未匹配清单"（>¥10,000需人工复核）
- [ ] 🔴 **强制8.5**：蓝字总额 - 红字总额 = 净应收总额（金额验算）

## 🚦 验证失败处理

### 如果任何一项强制检查失败：

1. **立即停止**：不继续后续步骤
2. **报告错误**：明确指出哪一项失败
3. **提供证据**：列出失败的具体数据
4. **要求修正**：给出修正建议
5. **重新验证**：修正后重新执行完整检查

### 示例：

```
❌ 强制检查失败！

失败项：强制2.8 - 发票ID重复
失败证据：
  - 发票ID: 25112000000113489041 出现2次
  - 客户: 苏州赛益生物有限公司

修正建议：
  1. 检查是否为同一文件被重复下载
  2. 检查文件名和内容是否一致
  3. 删除重复文件
  4. 重新执行完整验证

状态：❌ 对账流程已停止，等待修正
```

## 🚨 新增：第10步 - 业务逻辑验证（最关键！）

### 异常回款率预警（6项）

- [ ] 🔴 **强制10.1**：计算每个客户的回款率
- [ ] 🔴 **强制10.2**：标记回款率30%-70%的客户为"异常"
- [ ] 🔴 **强制10.3**：对异常客户，检查是否多开/重复开票
- [ ] 🔴 **强制10.4**：对异常客户，检查发票号码和日期
- [ ] 🔴 **强制10.5**：生成"异常回款率预警清单"
- [ ] 🔴 **强制10.6**：在报告中明确提示：可能多开发票，需人工核对

### 判断标准

| 回款率 | 判断 | 处理建议 |
|--------|------|----------|
| 0% | 正常欠款 | 催款 |
| 1%-29% | 正常欠款 | 催款 |
| **30%-70%** | **⚠️ 异常** | **检查是否多开票** |
| 71%-95% | 正常欠款 | 催款 |
| 96%-100% | 已收款 | 无需处理 |
| >100% | 多收款 | 检查是否有预付款 |

### 异常预警模板

```
⚠️ 异常回款率预警

客户：苏州赛益生物有限公司
净应收：¥200,000
实收：¥100,000
回款率：50.0%

⚠️ 可能的问题：
1. 多开发票：是否重复开了2张¥10万？
2. 发票金额错误：应该开¥10万，错开成¥20万？
3. 业务变更：原本¥20万订单，后来只执行了¥10万？

✅ 建议处理：
1. 核对业务合同/订单
2. 确认实际应收金额
3. 如多开，立即冲红多余发票
4. 不要催款（客户可能没欠钱）
```
